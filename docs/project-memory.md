# Durable project memory

Project memory holds facts and decisions the user explicitly saves for an opened workspace. It is not a transcript, a compaction summary, or an automatic extraction from chat. Open **Project memory** (brain icon) in the agent pane to add a topic and fact, record a source label or file reference, edit a correction, turn off its use, or delete it after confirmation. Duplicate topics are rejected so corrections update the existing item. The file reference is entered by the user; the app does not verify its contents or track later file changes.

The main process stores these records in a separate `memories.json` file under Electron's user-data directory, scoped by the opened workspace's absolute root. Each record has creation and update timestamps. The renderer has only narrow list/save/delete IPC operations; it cannot choose another workspace root. Input lengths and item counts are bounded. Unlike the API key, **project memory is not encrypted**. Do not store passwords, keys, or other secrets. Deletion is permanent; disabling an item keeps it available for review but excludes it from future prompts.

For a new OpenAI run, the main process loads that workspace's records. Only enabled items with word overlap against the current prompt are selected, with at most six included. A zero-match item is omitted, even if enabled. Selected items enter the first request as labeled reference data with topic, value, source, and update time, and the chat records which topics were sent. They remain distinct from fresh on-disk excerpts, recent visible chat messages, and provider-managed response-chain state. An item does not grant tool permissions or override the current user request; the model is instructed to treat it as potentially stale. The user must explicitly save changes—chat and compaction checkpoints never silently become memory.

This is a deterministic lexical starting point, not a guarantee of recall or truth. A later pass should evaluate relevant-memory retrieval on realistic tasks, stale and contradictory facts, privacy expectations, and restart behavior before adding automatic suggestions or semantic indexing. File references are provenance labels, not automatically validated citations.
